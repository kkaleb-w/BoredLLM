# 17. Reconnaissance

Findings from two scouting passes run before any build. One covered existing tooling for a
synthetic web; the other covered what is already known about this design's two fatal risks.

**Sourcing note.** Every arXiv identifier below was independently opened and its title,
abstract, and stated result confirmed, except where marked unverified. Search summaries and
agent reports are not evidence on their own.

---

## Part A. Existing tooling for a synthetic web

The requirement was four things at once: frozen and reproducible, servable locally as text
pages with link structure, containing information the model cannot predict, and browsable with
chosen attention.

### What exists

| Tool | Class | What it gives | What it lacks |
|---|---|---|---|
| **Kiwix / kiwix-serve + ZIM archives** | Frozen real content | Very mature, GPLv3, the de-facto standard for offline web content (Internet-in-a-Box, RACHEL, Kolibri). Human-authored corpora (Wikipedia, Wiktionary, Stack Exchange, Project Gutenberg, TED) served locally as real pages with working links, title and full-text search, and a link graph. Reproducible, pinned by archive. | No web-like power-law page topology across documents |
| **pywb / WARC + Common Crawl slices** | Frozen real content | Serves real archived web pages from WARC records, fully reproducible | Heavy; same topology gap |
| **BrowseComp-Plus (fixed corpus)** | Frozen real content | A fixed corpus (about 100k documents, roughly 1.1 GB) of real text with gold evidence labels | No page-level link structure between documents |
| **OpenResearcher offline corpus** | Frozen real content | Research release, large token corpus plus retriever and trajectories | Not a product; not a web |
| **Yioop synthetic page generator** | Synthetic topology | Generates pages with configurable document length and link behaviour, including a domain-versus-path link probability. Deterministic. | Pages are semantically empty |
| **Academic web-graph models** (RMAT, Bollobás–Riordan, ProWGen, Python Web Graph Generator) | Synthetic topology | Mature, peer-reviewed power-law topology generators, decades of literature | No content at all |
| **INetSim / INetMock** | Network simulation | Fakes DNS, TLS, HTTP at the network layer | Only relevant if the creature has a shell and could bypass a provided interface. Overkill otherwise |
| **Fictionet (Amla Labs)** | Commercial | Closed source, positioned for agent security evaluation and RL | Closed, and outside the project's control |
| **The-Dead-Internet** | Toy | A simulated internet stack with auth, social feed, search, MCP | Proof of concept, built quickly, and content is generated by the agents themselves, which is the mirror problem. License unclear, so treat as unusable |

### The finding that matters

**No single tool satisfies all four requirements.** The field splits cleanly into three groups:
tools with frozen real content but no web topology, tools with web topology but no content, and
"fake internet" projects with neither. The third group is also where the confound lives: those
projects are built by generating content with a language model, so the creature would read its
own cousin's output, which is exactly what the design must avoid.

### Recommendation

Assemble rather than adopt:

1. **Content:** a frozen human-authored corpus. Kiwix ZIM extraction, a BrowseComp-Plus style
   fixed corpus, or a Common Crawl slice.
2. **Structure:** a deterministic assembler that emits static pages with real link markup over
   a power-law topology, seeded so the same seed reproduces the same world. A reasonable
   starting point is a Zipf distribution over in and out degree (values around 2.1 and 2.7 have
   been used in web-graph work), a small number of dense hubs, a large number of thin stubs,
   and cross-domain links.
3. **Serve:** locally, frozen, read-only.

**Unverified:** arXiv:2608.21898, "Training Needs Trustworthy Worlds: Verified Synthetic Web
Environments for Agent Learning," appeared in search results but the page could not be opened
at the time of writing. Worth a look before building, since it is the closest-sounding thing to
this exact problem.

## Part B. The two fatal pilot risks

### Risk 1: instruction-free continuation, and the omniscient narrator

**The single most useful result of the whole reconnaissance.**

**Zhang, X. (2026), "The Curse of Knowledge in Role-Playing Language Models," arXiv:2610.17327.**
Verified. 480 scenes, each with a counterfactual twin that changes only a hidden fact, so any
mention of the twin's fact measures guessing. Across 11 open-weight models, characters use
content from speech they cannot hear at **67 and 72 percentage points above that baseline**,
even though most models can correctly state what the character perceives. The leak extends to
hidden actions and private messages and changes where characters search.

Three findings that bear directly on this project:

1. **Compliance depends on input format.** Changing only the scene layout or the character
   description raised the leak rate in two otherwise compliant open-weight models from **under
   10 percentage points to over 60**.
2. **Writing the line as the scene's author leaks nearly as much as role-play.** So "just
   narrate it neutrally" is not a fix.
3. **The fix is stated and demonstrated:** *"Giving models only what the character observes
   stops the leak without hiding what it may report."*

**Design consequence, and this is a change to the plan.** The state handed to the creature must
contain **only what the creature can observe**, not a world-state dump. Not "here is the room
and here is everything in it," because an author-level vantage produces author-level behavior.
It must be what this entity, in this body, at this moment, perceives. The world can hold
everything. The creature's input is a view from inside it.

**The Assistant Axis, Lu and colleagues (2026), arXiv:2601.10387.** Verified. The leading
component of the model persona space is an "Assistant Axis" capturing how far the model is
operating in its post-training default identity. Steering away increases the tendency to
identify as other entities; extreme steering induces a theatrical register. The axis is also
present in pre-trained models.

**Design consequence.** A base model is strongly preferable to an assistant-tuned one, since
the assistant identity is the trained default and the thing to be avoided. Reportedly, base
models continue text natively while instruct models treat input as a request and require
coercion to continue. That last claim is well grounded in mechanism but the sources are
authoritative commentary rather than a controlled experiment, so treat it as strong prior
rather than result.

### Risk 2: drift versus loop

**"LoopGuard: Breaking Self-Reinforcing Attention Loops via Dynamic KV Cache Intervention,"
arXiv:2604.10044.** Verified. Self-reinforcing loops arise from attention-head collapse onto a
narrow suffix, then get stabilized by KV-cache reuse, with each appended token reinforcing the
loop. Stated to be **more pronounced in smaller LLMs, where loops are easier to trigger and
harder to escape.**

Related verified work: attractor cycles under successive paraphrasing, and self-consuming
training loops that collapse in diversity, sometimes in under ten generations.

**Design consequence.** The exact worst case for this project is a small local model appending
its own output. So the loop risk is not hypothetical, it is the predicted failure mode for this
configuration. Levers: a context and KV growth policy, periodic memory compaction, and
importantly a **fresh external observation every tick**, which is the mechanism the design
already specifies and now has a reason to protect. This is why the world must supply real input
at every tick rather than only at the start.

### The pilot protocol this suggests

- Sweep temperature {0, 0.7, 1.0} against perturbation magnitude {none, small, large} against
  model type {base, instruct}.
- Include a **positive control for unbounded drift**: a tick that deliberately inverts meaning,
  to confirm the system can move at all.
- Include a **positive control for sustained non-collapse**: a condition with fresh external
  observation each tick.
- Watch context and KV growth as a confound rather than a nuisance.
- **Success criterion:** the model continues the state with neither assistant artifacts nor
  omniscient-narrator artifacts, when given only what the entity observes.
